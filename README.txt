SRC-Hunter-AI v2.1.0 - Windows x64 单文件版（闭源发布）

================================================================
一、这是什么
================================================================
自动化 SRC 漏洞线索发现工具，两种模式：
  1. Web 模式：资产收集(subfinder/crt.name/RapidDNS/httpx) -> URL 收集
     (katana+gau) -> 识别可测点 -> 8 类无害轻量测试 -> AI 复核 -> 只输出异常
  2. 代码审计模式：对 GitHub 开源仓库做静态扫描(20+ 跨语言危险模式规则 + 6 类硬编码密钥检测) -> AI 复核降噪 -> 按严重度输出
安全承诺：不写 PoC/EXP，不做 WAF 绕过，不深入利用；测试请求全部无害
(不删数据/不改配置/不读敏感数据/不批量取数)。
法律边界：仅限已获书面授权的 SRC 目标或自有系统，未授权渗透测试违法。
================================================================
二、首次配置（必需）
================================================================
1. 在本文件所在目录创建 .env 文件（exe 从同级目录读取），内容：
     OPENAI_API_KEY=sk-你的key
     OPENAI_BASE_URL=https://api.openai.com/v1   （任何 OpenAI 兼容中转均可）
     OPENAI_MODEL=gpt-4o-mini                    （按你的中转支持的模型填）
2. 外部工具（Web 模式需要，代码审计模式不需要）：
     subfinder / httpx / katana / gau （projectdiscovery 官网下载）
     放进 PATH，或在 .env 里写绝对路径，如 SUBFINDER_BIN=D:\tools\subfinder.exe
3. 不配 AI Key 也能用：降级为纯规则判断，异常项置信度固定 60%。
================================================================
三、Web 模式用法
================================================================
src-hunter-ai.exe --target example.com
    域名目标：子域收集 -> 探活 -> URL 收集 -> 测试 -> 异常报告
src-hunter-ai.exe --target 1.2.3.4
    单 IP（httpx 直连探活）
src-hunter-ai.exe --target 10.0.0.0/24
    C 段（上限 256 主机）
src-hunter-ai.exe --target a.com,1.2.3.4,10.0.0.0/24
    混合多目标（逗号分隔）
src-hunter-ai.exe urls.txt
    直接传 URL 列表文件（Burp 导出等，每行一个）
可选参数：
  --tests "SQL注入,越权"    只跑指定测试类型（13 类无害测试：越权/XSS/SQL注入/SSRF/
                          逻辑漏洞/开放重定向/文件上传/敏感路径/模板注入/
                          命令注入/CORS/JSONP劫持/目录列表）
  --all-urls               URL 列表模式：静态页面也做一次无害 GET 探测
  --concurrency 8          测试并发线程数（默认 5，上限 20）
  --no-ai                  跳过 AI 复核，仅规则判断
  --fresh                  清除收集缓存，强制重新收集
  --output D:\out          指定输出目录（默认 ./output）
输出：output\anomalies_*.txt/.json/.csv（只含异常项 + 按类型摘要）

四、代码审计模式用法（开源项目 SRC）
================================================================
src-hunter-ai.exe --repo https://github.com/xxx/yyy
    clone 并审计（需本机有 git；有缓存，重复审计秒级完成）
src-hunter-ai.exe --repo D:\code\yyy
    审计本地仓库
src-hunter-ai.exe --repo url1,url2,url3
    批量审计（逗号分隔）
src-hunter-ai.exe --repo <仓库> --sev high
    只看高危（可选 high/medium/low）
src-hunter-ai.exe --repo <仓库> --sev medium --top 10
    中危以上，每严重度只留前 10 条
src-hunter-ai.exe --repo <仓库> --no-ai
    跳过 AI 复核
输出：output\code_audit_*.txt/.json（文件:行号 + 规则 + 代码行 + 按仓库摘要）
内置降噪：常量赋值跳过 / 测试文件发现降级 / 占位符密钥丢弃 / 增量缓存
(重跑未变更仓库 AI 调用为 0)。
注意：AI 复核是降噪不是定论，所有发现需人工确认后才可提交 SRC。

五、常见问题
================================================================
Q: 提示找不到 subfinder/httpx？  A: Web 模式需要；下载后放 PATH 或 .env 指路径。
Q: 访问 GitHub 超时？            A: 挂代理（工具自动读系统代理环境变量，
   或 git config --global http.proxy http://127.0.0.1:7890）
Q: 目标返回 429/503？            A: 工具自动判为限流不报异常，降低并发或稍后再测
Q: 报告能直接交 SRC 吗？         A: 不能。报告是线索清单，逐条人工验证后自行撰写报告
